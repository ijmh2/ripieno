That column normally holds one name

Whoever's laptop ran the commit. Here, three agents belonging to three different people write to one repository at the same time. 

$ npm run demo:provenance

$ git log --pretty='%<(16)%an  %s' -5

  Alex's agent      Mention the limits in the README
  Sam's reviewer    Write down both limits
  Mira's coder      Bound the transcript
  Sam's reviewer    Cover the rate limit
  Mira's coder      Add rate limit to relay

Real output — a script in the repository, running the actual code against a real repository, writing concurrently rather than in turn. Git serialises on .git/index.lock, and losing that race is how five writes in six once vanished.

Nothing runs in the middle

Each person's agent runs on their own machine, under their own permissions, on their own subscription. The relay routes messages and keeps track of who said what. It holds no code and executes nothing.

Attribution

Every action names its author and its machine

That second column does not normally exist. It is the difference between knowing an agent changed a file and knowing whose agent changed it, where.

Roles are enforced in the relay, not by hiding buttons — anyone can send the message a hidden button would have sent.

Work · 3 · 1 failed
  • ✓Mira's coder wrote room.ts on @mellery
  • ✓Kate's agent read latest.json on @swhitfield
  • ✕Sam's reviewer ran npm test on @swhitfield — exit 1

Consent

Nothing reaches your disk unasked

When somebody else's agent wants to write a file or run a command on your machine, it stops and asks — naming the agent, its owner, and the command.

A refusal is attributed too. A specific person declined a specific action, and the room says so out loud rather than the agent failing into silence.

Mira Ellery's agent wants to run Bash
npm test -- --runInBand
Allow once Deny

Other members can influence this request. This summary does not show the full exact input, so approval can apply to this run only.

Bring your own

Everyone attaches an agent they already pay for. Nobody shares a login, which is what makes attribution mean anything in the first place.

Self-hosted

There is no service in the middle

Solo mode runs the relay inside your editor — nothing deployed, no account, no token. A shared room runs on a relay you operate, and it tells you everything you need on boot.

There is no hosted option because a relay sees every message and routes every tool call. You run your own, or you run none at all. 

$ docker run -p 8787:8787 -v ripieno-data:/data ripieno-relay

  Ripieno relay ready

    URL     wss://relay.example.com
    Token   dd0bce7f…50fe0f1  (generated, saved)
    Room    general
    Members verified against GitHub

Getting started

Two of these need nothing but an editor.

  1. Install it

    Not on the Marketplace yet — this is a 0.0.1 Preview, so you install a .vsix.

    git clone https://github.com/ijmh2/ripieno
cd ripieno && npm run setup

    Builds, packages and installs into whichever editor you have.

  2. Start a room for yourself

    Open the Ripieno panel and press Start a room. No relay, token or account — the extension runs one inside the window. It is the same relay a team shares, not a reduced imitation.

  3. Add somebody else

    That needs a relay you both can reach. One command, and it prints what to hand over.

    docker run -p 8787:8787 -v ripieno-data:/data ripieno-relay

    Running your own relay covers three ways, in increasing order of effort.

What's actually real

An unknown repository has no other way to earn anything.

Works, used

Solo mode, invite links, rooms over a deployed relay, several agents per member, remote workspace tools, approval-gated side effects, the action log, verified GitHub identity, roles, and history that survives a redeploy.

Built and tested, never deployed

The shared-workspace container — including real git integration tests. It has never run anywhere but a test.

Not shipped

Hosted mode. It compiles and its unit tests pass, and it has never run against a live session — so it is not a feature and is not described as one.

Two people have ever used this, and one of them wrote it. Several bugs were found only by those two, and several more by an outside reading of the whole repository. Read the long version.
