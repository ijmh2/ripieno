That column normally holds one name

Whoever's laptop ran the commit. Here, three agents belonging to three different people write to one repository at the same time — and git log names each of them. 

$ npm run demo:provenance

$ git log --pretty='%<(16)%an  %s' -5

  Alex's agent      Mention the limits in the README
  Sam's reviewer    Write down both limits
  Mira's coder      Bound the transcript
  Sam's reviewer    Cover the rate limit
  Mira's coder      Add rate limit to relay

Three names, where every git log you have ever run had one.

A shared login makes an agent useless to a team

Put two people behind one session and the agent sees one user changing their mind. It cannot tell agreement from disagreement, whose preferences to honour, or whose filesystem the next write lands on.

Here every message the agent receives carries its author as structure the relay maintains — not a prefix the model can ignore — and every workspace action runs on the asking member's own machine, under their own permissions.

Everything has an author

The action log records that Mira's coder wrote room.ts on @mellery while Kate's agent read a file on @swhitfield. The machine is part of the record, not an assumption.

Nothing reaches your disk unasked

When somebody else's agent wants to write a file or run a command on your machine, it stops and asks — naming the agent, its owner and the command. Your refusal is recorded under your name rather than failing silently.

Bring your own agent

Claude Code, Codex on your ChatGPT plan, Gemini, any OpenAI-compatible endpoint, or a local model through Ollama. Nobody shares a login, and the room resells nobody's inference.

Self-hosted, or no host at all

Solo mode runs the relay inside your editor — nothing deployed, no account, no token. A shared room runs on a relay you operate. There is no service in the middle, because a relay would see every message you send.

Getting started

  1. Install it

    Not on the Marketplace yet — this is a 0.0.1 Preview, and the honest version of that sentence is that you install a .vsix by hand. 

    git clone https://github.com/ijmh2/ripieno
cd ripieno && npm run setup

    Builds it, packages it, and installs it into whichever editor you have.

  2. Start a room for yourself

    Open the Ripieno panel and press Start a room. No relay, no token, no account — the extension runs one inside the window. It is the same relay a team shares, not a reduced imitation.

  3. Add somebody else

    That needs a relay both of you can reach, which takes one command and prints everything you need to hand over. 

    docker run -p 8787:8787 -v ripieno-data:/data ripieno-relay

    Running your own relay covers the three ways to do it, in increasing order of effort.

What's actually real

An unknown repository has no other way to earn anything, so the README carries a table of what works, what has been built but never deployed, and what is not shipped at all. Hosted mode is in the third column. The shared-workspace container is in the second.

Several bugs were found only by two people using it, and several more by an outside reading of the whole repository. Two people have ever used this. One of them wrote it.
